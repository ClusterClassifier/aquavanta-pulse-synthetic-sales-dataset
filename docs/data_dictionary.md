# Data Dictionary

## Scope

This dictionary describes `clean/model_ready_daily.csv`, the primary flattened table generated by `data_generator.ipynb`. It contains 105,216 rows and 58 columns at the grain:

```text
date × city × channel × SKU
```

The relational CSVs contain subsets or aggregations of these fields. The raw data-cleaning edition adds `source_record_id` and intentionally introduces missing values, duplicates, inconsistent labels, mixed date formats, and inventory reconciliation errors.

All values are synthetic. They do not describe an actual product, company, customer, or market.

## Availability labels

The final column in each table indicates when a field becomes available:

| Label | Meaning |
|---|---|
| `ID` | Identifier or grouping key |
| `Pre` | Known or set before the day's sales outcome |
| `Forecast` | Known for historical analysis; a forecast would be required for future prediction |
| `Same day` | Accumulates during the day and is unavailable for a true advance forecast |
| `Post` | Outcome or end-of-day measure; do not use to predict the same day's sales |
| `Delayed` | Generated from purchases on an earlier date |
| `Mixed` | Availability depends on whether the event was planned or unexpected |

## Pricing and competition

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `list_price` | Float | Published AquaVanta price before discount. | INR; ₹2,499 or ₹2,599 | Pre |

The price-gap calculation is:

```text
(selling_price - competitor_median_price) / competitor_median_price
```

## Marketing and funnel

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `campaign_type` | String | Campaign operating for the row. | Always-on, Influencer, Counter-promotion | Pre |
| `allocated_ad_spend` | Float | Portion of the city-channel advertising budget allocated to the SKU. | INR | Pre |
| `impressions` | Integer | Paid-media impressions allocated to the SKU. | Count, non-negative | Same day |
| `clicks` | Integer | Paid-media clicks. | Count, `clicks ≤ impressions` | Same day |
| `product_page_views` | Integer | Online product-page visits; for retail, a digital-assisted footfall proxy. | Count, positive | Same day |
| `add_to_cart_count` | Integer | Add-to-cart actions or strong retail purchase intent. | Count, `add_to_cart_count ≤ product_page_views` | Same day |
| `conversion_rate` | Float | Potential demand divided by product-page views. | Decimal fraction, 0–1 | Post |

The funnel obeys:

```text
clicks ≤ impressions
potential_demand ≤ add_to_cart_count ≤ product_page_views
```

`impressions`, `clicks`, `product_page_views`, and `add_to_cart_count` may be useful for same-day nowcasting. They should not be used as if they were known in advance for a true future-demand forecast.

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `opening_inventory` | Integer | Stock available before receipts and current sales. | Units, non-negative | Pre |
| `replenishment_units` | Integer | Units received from earlier purchase orders. | Units, non-negative | Pre |
| `order_placed_units` | Integer | New replenishment order placed on the date. | Units, non-negative | Same day |
| `closing_inventory` | Integer | Stock remaining after receipts and fulfilled sales. | Units, non-negative | Post |

Every clean row satisfies:

```text
opening_inventory + replenishment_units - units_sold = closing_inventory
```

## Demand and sales outcomes

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `potential_demand` | Integer | Customer demand before cancellations and inventory constraints. | Units, non-negative | Post; recommended demand target |
| `units_ordered` | Integer | Customer units ordered. It equals potential demand in v1.0.0. | Units, non-negative | Post |
| `cancellation_units` | Integer | Units cancelled before fulfilment. | Units, non-negative | Post |
| `units_sold` | Integer | Units fulfilled after cancellations and inventory constraints. | Units, non-negative | Post; primary sales target |
| `lost_sales_units` | Integer | Fulfilment demand that could not be supplied because of insufficient stock. | Units, non-negative | Post |

The fulfilment relationships are:

```text
fulfilment_demand = units_ordered - cancellation_units
units_sold ≤ fulfilment_demand
lost_sales_units = fulfilment_demand - units_sold
```

Use `potential_demand` when studying unconstrained demand. Use `units_sold` when the task is specifically to forecast fulfilled sales. A model trained only on `units_sold` can learn artificially low demand during stockouts.

## Delivery, returns, and feedback

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `average_delivery_days` | Float | Average time from fulfilment to customer delivery. | Days, approximately 0–12 | Post |
| `return_units` | Integer | Units returned from purchases made approximately 14 days earlier. | Units, non-negative | Delayed |
| `return_rate` | Float | Return units divided by lagged sales eligible for return. | Decimal fraction, 0–1 | Delayed |
| `new_review_count` | Integer | Reviews linked to purchases made approximately 10 days earlier. | Count, non-negative | Delayed |
| `average_rating` | Float or missing | Mean rating among reviews posted on the date. Missing when no review was posted. | 1–5 | Delayed |
| `negative_review_share` | Float | Share of new reviews rated one or two stars. | Decimal fraction, 0–1 | Delayed |
| `primary_return_reason` | String | Dominant reason among returns represented by the row. | No return, Battery-cap defect, Late delivery, Changed mind, Colour mismatch, Expectation mismatch, Damaged in transit | Delayed |

Returns and reviews are intentionally lagged. Do not interpret them as feedback from the current day's sales.

## Revenue and margin

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `gross_revenue` | Float | Current fulfilled units multiplied by the current selling price. | INR | Post |
| `return_value` | Float | Refund value for returns from earlier purchases recognized on the date. | INR | Delayed |
| `net_revenue` | Float | Gross revenue minus return value. | INR; may be negative | Post |
| `gross_margin` | Float | Net revenue after product cost, channel fees, advertising, and return handling. | INR; may be negative | Post |

Revenue relationships are:

```text
gross_revenue = units_sold × selling_price
net_revenue = gross_revenue - return_value
```

These are outcomes. Using them to predict `units_sold`, `potential_demand`, or returns from the same row would cause target leakage.

## Event field

| Column | Type | Description | Units or values | Availability |
|---|---|---|---|---|
| `event_name` | String | Injected event affecting the row. Overlapping labels are separated by a vertical bar. | No event or one/more catalogue labels | Mixed |

Planned events such as campaigns may be known in advance. Unexpected outages, defects, strikes, and recalls should not be treated as advance-known variables unless the experiment explicitly assumes an alerting system.

## Raw-edition-only field

| Column | Type | Description | Units or values |
|---|---|---|---|
| `source_record_id` | String | Clean observation identifier from which the raw row originated. Duplicate values reveal injected duplicate source records after cleaning. | `AVP-000001` pattern |

In `raw/model_ready_daily_raw.csv`, `record_id` is replaced with a `RAW-` export identifier. The raw file deliberately violates some clean-table expectations and should be cleaned before modelling.

## Recommended target and leakage rules

| Task | Suggested target | Avoid as same-row predictors |
|---|---|---|
| Future demand forecasting | `potential_demand` | Funnel outcomes, sales, returns, reviews, revenue, closing stock, stockout duration |
| Fulfilled-sales forecasting | `units_sold` | Demand and all downstream outcome fields |
| Return prediction | Future `return_units` or a derived return flag | Same-day return fields and feedback posted after the purchase |
| Stockout prediction | Future stockout flag derived from `stockout_hours` | Same-day closing inventory, lost sales, and stockout hours |
| Margin forecasting | Future `gross_margin` | Same-day revenue, return value, and gross margin |

For supervised modelling, split chronologically rather than randomly to reduce leakage across time. The recommended release split is training through December 2024, validation from January through June 2025, and testing from July through December 2025.
